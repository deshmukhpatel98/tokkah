Kin for macOS

A video call that should feel like the other person is in the room. This is the native half — built because a browser will not give you the clocks or the audio thread the goal requires.

Install

Download Kin-0.60.0.dmg

Open the disk image and double-click Kin. macOS warns once, because this is signed by us and not notarised by Apple: open System Settings → Privacy & Security, scroll down and click Open Anyway (or right-click the app → Open). That is the whole of it — after that single click the app moves itself into /Applications, clears its own quarantine, and keeps itself up to date, verifying an Ed25519 signature on every update before applying it. Nothing else to do. Dragging it to /Applications yourself still works, but it is not required.

Then double-click Kin.app, type a room name, press Join. Both people type the same name and you are connected directly, with no server in between.

Every call reports what it did to the call dashboard — latency, gaps in the sound, bandwidth, and anything that broke, live while the call is running and kept afterwards. No audio and no room names are ever sent; the room name is the encryption key and never leaves the two machines.

Or from a terminal

curl -fsSL https://room.tokkah.com/macos/install.sh | sh

For people comfortable with a terminal: no security prompt at all, because files fetched by curl are not quarantined, so this path never meets Gatekeeper. It installs the same app plus ~/.local/bin/tk, checks the download against a SHA-256 in a signed manifest, and self-updates from then on. Read the script first if you like — it is right here, 50 lines.

Use it

tk --room ripe-mango-jam --window

Pick any room name and run the same command on both Macs — that is the whole setup. They find each other through a rendezvous at room.tokkah.com, then talk directly, peer to peer, with no relay carrying your call. Two Macs on one wifi take the LAN path automatically; two Macs in different houses punch through both routers. The room name is also the encryption salt, so choose something only the two of you would say, and say it to each other rather than typing it anywhere.

--window opens the picture; without it you get audio and a latency read-out. Add --video camera to send your camera, or --video clip.mov to send a file. --display metal --fullscreen --vsync 0 is the lowest-latency picture — 3.8 ms to glass instead of 24.6, at the cost of some tearing. If both Macs are on the same network you can skip the rendezvous entirely with --peer 192.168.1.50:7001.

It asks for microphone and camera permission the first time. Because tk is a command-line tool it has no identity of its own, so macOS grants that to the terminal you launched it from — if it says the microphone was denied, enable Terminal (or iTerm, or VS Code) under System Settings → Privacy & Security → Microphone. It prints its latency budget on start and then one line a second.

These two are a simulated path, not two real machines. The delay, jitter and loss are injected on one Mac — real distance is the next thing to measure, and it will be worse in ways a rig cannot invent. What the numbers do establish is the part that is not the speed of light: about 12–14 ms of it, whatever the distance. Light through fibre is the floor nobody can move, so that residue is the only number worth optimising, and it is the one quoted here.

Measured between two processes on one Mac, so the network contributes nothing and both ends share one clock — these are the pipeline itself, not an estimate. Audio and video ride one UDP socket, so there is one port and one hole to punch. Keyframes are sent on request rather than on a timer, so a healthy call never pays for one and a late joiner recovers in about 300 ms.

Honest limits

Apple silicon only. It is a command-line tool that can open a window, not yet an app with buttons. Audio and video are encrypted with AES-256-GCM, keys agreed per call over X25519 and salted with the room code — so a listener on any hop gets nothing, and neither does anyone who was not told the code. What it does not stop is someone who knows the code and can sit in the middle of the path: that needs an identity that outlives a call, which does not exist here yet. It is uncompressed audio — 32-bit float, never re-encoded — which is why it sounds like the room rather than like a phone, and also why it wants about 2.4 Mbps in each direction, rising to 3.7 while it is repairing packet loss. On a thin uplink that is the first thing to notice. There is limited forward error correction: a lost packet is a concealed millisecond of audio, and a lost video frame is repaired by asking for a new keyframe, which costs about one frame. Two machines behind ordinary routers find each other with --room and talk directly, with no relay in the middle; a symmetric NAT on either side will defeat that, and there is no fallback yet when it does. It is signed by us, not notarised by Apple, so the .dmg costs you one click through a macOS warning the first time; the curl install skips even that. And it is an early build being changed several times a day — it updates itself, so it will not stay this one for long.
