Kin for macOS

A video call that should feel like the other person is in the room. It is a native app and nothing else — built that way because a browser will not give you the clocks or the audio thread the goal requires.

Install

Download Kin-0.118.0.dmg

Open the disk image and double-click Kin. macOS warns once, because this is signed by us and not notarised by Apple: open System Settings → Privacy & Security, scroll down and click Open Anyway (or right-click the app → Open). That is the whole of it — after that single click the app moves itself into /Applications, clears its own quarantine, and keeps itself up to date, verifying an Ed25519 signature on every update before applying it. Nothing else to do. Dragging it to /Applications yourself still works, but it is not required.

Then double-click Kin.app. There is nothing to fill in: it opens with your camera on and a call already running, and the link to it in the middle of the window. Click the link to copy it, send it to the other person, and they are in.

Or press the handset beside the link, type a name, and that Mac rings. Answer someone’s call once and they become a face on the panel, so calling them back is one tap. Kin rings when it is closed, too: it keeps a small thing in the menu bar from login onwards, so a call reaches this Mac without the app being open, and the card that appears shows the caller’s picture before you answer. Only theirs, and only if you have answered them before — a stranger rings as a name and nothing else, because drawing their picture would mean opening a connection to them before you had agreed to anything.

Every call reports what it did to the call dashboard — latency, gaps in the sound, bandwidth, and anything that broke, live while the call is running and kept afterwards. No audio and no room names are ever sent; the room name is the encryption key and never leaves the two machines.

Or from a terminal

curl -fsSL https://room.tokkah.com/macos/install.sh | sh

For people comfortable with a terminal: no security prompt at all, because files fetched by curl are not quarantined, so this path never meets Gatekeeper. It installs the same app plus ~/.local/bin/tk, checks the download against a SHA-256 in a signed manifest, and self-updates from then on. Read the script first if you like — it is right here, just under 160 lines, most of them saying why.

Use it

tk --room ripe-mango-jam --window

Pick any room name and run the same command on both Macs — that is the whole setup. They find each other through a rendezvous at room.tokkah.com, then talk directly, peer to peer. Every route the two Macs have is raced against the others by measured round trip and the quickest one wins: two Macs on one wifi take the LAN path automatically, two Macs in different houses punch through both routers. The room name is also the encryption salt, so choose something only the two of you would say, and say it to each other rather than typing it anywhere.

--window opens the picture; without it you get audio and a latency read-out. Add --video camera to send your camera, or --video clip.mov to send a file. --display metal --fullscreen --vsync 0 is the lowest-latency picture — 3.8 ms to glass instead of 24.6, at the cost of some tearing. If both Macs are on the same network you can skip the rendezvous entirely with --peer 192.168.1.50:7001.

It asks for microphone and camera permission the first time. Because tk is a command-line tool it has no identity of its own, so macOS grants that to the terminal you launched it from — if it says the microphone was denied, enable Terminal (or iTerm, or VS Code) under System Settings → Privacy & Security → Microphone. That is a property of the bare binary and not of the app: Kin.app is a signed bundle, so it owns its own permissions, asks in its own name, and can be reviewed and revoked like anything else on the Mac. tk prints its latency budget on start and then one line a second.

These two are a simulated path, not two real machines. The delay, jitter and loss are injected on one Mac — real distance is the next thing to measure, and it will be worse in ways a rig cannot invent. What the numbers do establish is the part that is not the speed of light: about 12–14 ms of it, whatever the distance. Light through fibre is the floor nobody can move, so that residue is the only number worth optimising, and it is the one quoted here.

Measured between two processes on one Mac, so the network contributes nothing and both ends share one clock — these are the pipeline itself, not an estimate. Audio and video ride one UDP socket, so there is one port and one hole to punch. Keyframes are sent on request rather than on a timer, so a healthy call never pays for one and a late joiner recovers in about 300 ms.

Honest limits

Apple silicon only, and a Mac only — there is no Windows, Linux, iPhone or Android build, and no browser call any more. Audio and video are encrypted with AES-256-GCM, keys agreed per call over X25519 and salted with the room code — so a listener on any hop gets nothing, and neither does anyone who was not told the code. What it does not stop is someone who knows the code and can sit in the middle of the path. There is an identity that outlives a call now — your Mac keeps a key, and a call from a name you have answered before is checked against the key it used last time — but that key is not yet tied to the one the call is encrypted with, so it does not close this. There is no lossy codec anywhere in the audio, nothing that throws away the parts of a voice a model decided you would not miss, which is why it sounds like the room rather than like a phone. What it does do is cut the 32-bit float macOS hands over down to 16 bits, and then compress that losslessly — 2.6×, bit for bit, no packet ever falling back to a raw copy. The compression costs nothing at all. The 16-bit step is the one real loss and it measures 73 dB signal-to-noise end to end, which is below the self-noise of any microphone this will run on. Together that is 1.16 Mbps in each direction, and it climbs while the path is losing, because every packet then carries a copy of the one before it. On a thin uplink that is still the first thing to notice. Beyond that copy there is no forward error correction: a lost packet on a clean path is a concealed millisecond of audio, and a lost video frame is repaired by asking for a new keyframe, which costs about one frame. Two machines behind ordinary routers find each other and talk directly, with nothing in the middle; when the routers will not allow that, or when a relay is measurably the shorter wire, the call goes through Cloudflare’s relay instead — sealed with the same key, which the relay does not have. It is signed by us, not notarised by Apple, so the .dmg costs you one click through a macOS warning the first time; the curl install skips even that. And it is an early build being changed several times a day — it updates itself, so it will not stay this one for long.
